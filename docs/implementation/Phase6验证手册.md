> **2026-10-15 变更：工具由木斧改为燧石。** §1–§9 是在**木斧**下验收通过的；机制（回调、返回值、渲染）一行未变，
> 仅 `SelectionTool.active(...)` 里判定的物品由 `Items.WOODEN_AXE` 换成 `Items.FLINT`，故上面 9 条结论沿用。
> 但"手持燧石"这一组合本身**尚未在游戏内跑过**，且 §5 的代价描述随之改变——请以 §10 / §11 复核。
> 换物品的理由：燧石原版无左键行为、无右键用途，当"魔杖"的代价只剩"左键挖不动方块"（裸手速度，本就不实用）。

> **2026-10-15 增补：选区功能加了总开关 + HUD。** 之前"开启"就等于"手持燧石"，没有独立开关；
> 现在多了一个键位（默认 **J**）切换，`SelectionTool.isEnabled()` 是唯一的开关状态，HUD 显示它。
> 判定条件变成"客户端侧 + **开关已开** + 手持燧石 + 没在跑测试"。**默认开启**，所以 §1–§11 的行为不变。
> 开关关闭时 HUD 整行不画（对应你说的"没有开启就隐藏"）。

> **2026-10-15 再改：HUD 还要求手持燧石。** 原本只要开关开着就显示，因此拿别的东西（甚至空手）时也会看到
> `[WRT] 选区工具：开启`——那句话在那种场合没有意义。现在 `SelectionHud.render` 的两个条件与
> `SelectionTool.active()` 的前两条对齐（**开关已开 + 手持燧石**），不满足就整块不画。
> §14 的"显示"部分仍成立（它本来就是在手持燧石时验的），新增 §16 复核"手持其他物品时不显示"。

> **2026-10-17 增补（多人支持验收后）：换连接的会话复位 + 编辑器"新建"复用燧石选区。**
> 两处都源自 §24 / §31 备注里报的现象：
> 1. **换连接时复位客户端会话状态**（§33 / §34）。`ClientTestState` 从"直读单例"换成"网络镜像"后漏了复位路径——
>    服务端是**边沿触发**广播（空闲→空闲不发），所以"最后收到 `running=true`、却在测试结束前就断了线"的客户端
>    会**永久卡在"正在跑测试"**：燧石选不了点、编辑器打不开，而选区 HUD（不查 `isRunning`）照旧显示"开启"。
>    现在在 `ClientPlayConnectionEvents` 的 JOIN / DISCONNECT 上复位镜像，并按 UUID 清掉本客户端的选区。
> 2. **编辑器"新建"改用燧石选区**（§35）。原先 `TestEditorScreen.createNew()` 一律用 `client.player.getBlockPos()`，
>    于是"用燧石圈好了范围、点编辑器新建却建在脚底下"。现在两条新建入口同义：有选区就用选区（`origin` 取 min 角，
>    与 `/wrutils test new` 一致），没选区才退回玩家脚下。

> **2026-10-16 新增：测试进度 HUD（§17–§21）。** 跑测试时在**屏幕左上角**显示进度，没在跑就整块不画。
> 引擎在 `onEndWorldTick` 里**每 tick 由服务端线程重建整份不可变快照**（`TestProgress`），
> 客户端只读那一个 `volatile` 引用——不逐字段读 `TestRun`，否则渲染线程会读到跨 tick 的混合值。
> 放**左上角**而不是像选区 HUD 那样放左下角：左下角是原版聊天区，而测试结果本来就打在那里。

## 怎么测 · 选区工具

**前置**：改的是 Java，**必须重启游戏**（不是重进存档）。

1. 起一个单人存档，手里拿着**燧石**（`minecraft:flint`）。
2. 对着一块方块**左键** → 动作栏出现 `[WRT] pos1 = (...)`；换另一块**右键** → `pos2`。
3. 输入 `/wrutils sel info` → 打印的 `pos1/pos2/min/max/体积` 应与刚才两次点击一致，同时世界里应出现围住该范围的青色线框。
4. 换一把别的工具（比如石镐）重复左/右键 → 应**正常挖掘/交互**，动作栏没有 `[WRT]` 消息。
5. `/wrutils test new axe_probe` → 打开 `run/saves/<世界名>/wrutils1_21_11/tests/axe_probe.json`。
   `origin` 会取选区的 `min` 角，`area.input[0]` 应是 `{"min":[0,0,0], "max":<选区跨度>}`——坐标一律是**相对 origin** 的偏移。
6. `/wrutils sel clear` → 线框消失。
7. **手持燧石**时按 **J** → 动作栏出现 `[WRT] 选区工具：关闭`，左下角整块消失；再按一次恢复两行。
8. 开关关闭时手持燧石左键挖方块 → 应能正常挖掉，动作栏没有 `[WRT]` 消息。
9. 换成石镐（或空手）→ 左下角**整块不显示**，无论开关开着还是关着。
10. 按 **F1**（隐藏 HUD）→ 左下角那两行应跟着整个 HUD 一起消失。

## 怎么测 · 进度 HUD

**前置**：同样**必须重启游戏**。建议把 `timeoutTicks` 调大一点（或在编辑器里改），不然 60 tick 一晃就过去了、看不清。

1. `/wrutils test run redstone_dust_power` → 左上角立刻出现两行：`[WRT] 运行中 redstone_dust_power`
   与 `步骤 x/y  断言 n  失败 m  tick t/T`。
2. 盯着看：`tick` 应每 tick +1；跑到 `use`/`assert` 的 tick 时 `步骤` 会跳；跑完**整块立刻消失**。
3. 故意造一个会失败的测试（例如把某条 assert 的期望值改错）后运行 → 第二行应**整行标红**。
4. `/wrutils test runall` → 末尾应多出「队列剩 k」，且每跑完一个测试 k 递减；单跑时不出现这一段。
5. 没跑任何测试时，左上角**应当是空白**。按 **F1** → 这两行跟着整个 HUD 一起隐藏。

## 怎么测 · 多人服务器支持

**前置**：改的是 Java，**两端都要重启**——客户端重启游戏，服务器重启进程。
多人这套环境怎么起、`online-mode` 与 `player001` 怎么配，见[交接文档](handoff-2026-10-17.md)的「环境」一节，不在这里重复。

**先单人，后多人。** §22–§24 是回归线，不是走过场：这三条覆盖的功能在本轮**换了数据来源**
（直读单例 → 网络 payload），单人下如果不先确认没坏，多人出问题时你会分不清是哪一边的锅。

### A. 单人回归（§22–§24）

照 §1–§21 的老流程走一遍即可，重点看三处：

1. 按 **K** → 编辑器列表**能出来**（会先闪一下"加载中…"）。
2. 点右侧任一测试 → 详情出现；改一个值 → "保存" → 回列表再点开，改动能读到。
3. 跑一个测试 → 左上角进度 HUD 出现并逐 tick 走；燧石选两角 → 线框在 → `/wrutils test new <id>` 生成成功。

### B. 多人（§25–§32）

4. 用 IDEA 的 `Minecraft Client` 起客户端、`Minecraft Server` 起服务器（**不要**同时用 `run-server.bat`，
   两者互斥，见交接文档）。以 `player001` 进服务器。
5. 按 **K** → 应能打开编辑器；列表里能看到该存档 `tests/` 下的全部测试。
6. 点"新建" → 改 id 与内容 → "保存" → 到服务器机器上看 `run-server/wrutils1_21_11/tests/<id>.json`。
7. 点"运行" → 服务器上跑起来，**客户端**左上角进度 HUD 跟着走（这条最值得盯：它跨了进程）。
8. 运行中再按 **K** → 应被拒绝。
9. 手持燧石选两角 → 在**聊天框**里敲 `/wrutils test new sel_probe`（注意：这条命令在服务端执行，
   它读的是**服务端**那份选区）→ 生成的 `area.input` 应与线框一致。

**§32 需要一个未 op 的账号**（改 `run-server/server.properties` 的 `online-mode=false` 后随便换个名字即可，
注意该名字的 UUID 随之变化、不会有 op）。嫌麻烦可以跳过，这条只是确认权限校验确实生效。

## 失败时看哪里

- **线框位置整体偏移/画不出来**：坐标约定抄自原版 `WorldRenderer.drawBlockOutline`（`VoxelShapes` 用绝对坐标、偏移量传 `-相机位置`）。
  若位置不对，八成是 `WorldRenderContext.matrices()` 与预期不符——`SelectionRenderer.render` 里改用 `context.matrices().push()/translate()/pop()` 包一层即可。
- **线框颜色不可见**：颜色必须是**不透明 ARGB**（`0xFF......`）。Phase 5 踩过这个坑——alpha 为 0 的颜色在本版本渲染为全透明。
- **燧石拦不住挖掘，或拦过头把别的也拦了**：查 `SelectionTool.active(...)` 的三个条件（客户端侧 / 手持燧石 / 未在跑测试），
  以及返回值——必须是 `ActionResult.FAIL`（**取消且不发包**）；返回 `SUCCESS` 会把交互再往服务端送一遍。
- **动作栏没消息**：`player.sendMessage(Text, true)` 走的是动作栏；若被别的 HUD 覆盖，先看聊天记录里的 `/wrutils sel info`。
- **进度 HUD 不出现 / 数字不动**：它读的是 `WrtTestEngine.progress()`，由 `onEndWorldTick` **每 tick** 重建；
  且只在"测试确实跑在自己那个维度"时才更新。一直空白就先确认 `run` 真的在跑（聊天里应已有报告行）。
- **进度 HUD 位置不合适**：坐标写死在 `ProgressHud.MARGIN`（当前 4,4，左上角）。要挪到别处改这一个常量。
- **多人下编辑器一直"加载中…"或干脆没反应**：先看**服务端**日志有没有 `WrtTestEngine attached`。
  收到包但权限不够会被静默拒绝成一条错误消息（应显示"需要 OP 权限"）；连错误都没有的话，
  八成是 payload 没注册上（`Wrutils1_21_11.onInitialize` 里的 `WrtNetworking.registerPayloads()`）。
- **提示"该服务器没有安装 WRT"**：这是 `ClientPlayNetworking.canSend(...)` 为 false，即对面确实没装这个 mod
  （或握手还没完成）。原版服务器上装客户端 mod 就是这个现象，**属预期**。
- **单人下编辑器列表加载不出来**：先确认"暂停时包还处理不处理"这前提没变——
  这是本轮的**关键假设**：集成服务端暂停时 `MinecraftServer.processPacketsAndTick` 仍然无条件调用
  `packetApplyBatcher.apply()`（反编译核对过；开背包世界暂停但物品照常移动也是同一个道理）。
  如果这个假设在某版本失效，编辑器在单人下会**永远停在"加载中…"**——那就是它，不是网络层写错了。
- **多人下保存"成功"了但服务器上没有文件**：看服务端日志的 `[WRT] <玩家> 保存了测试 <id>` 有没有出现。
  没有的话说明请求根本没到 `TestEditorServer.writeDefinition`。
- **"手持燧石选不了点，但左下角还写着『选区工具：开启』"**：这两个判据本来就不一致——
  `SelectionTool.active()` 多查一条"没在跑测试"，而 `SelectionHud` 只查前两条。所以症状说明
  **`ClientTestState` 以为有测试在跑**。正常情况下它会随连接复位（见 `ClientTestState.reset()` 的注释）；
  若仍复现，去看是不是服务端的 idle 推送没发出去（`TestStatusServer` 是**边沿触发**，只在状态变化那一 tick 广播）。

- **进度 HUD 只显示"当前正在跑的那一个"测试**：批跑 `runall` 时也只显示当前这个，
  靠末尾的「队列剩 k」看还剩几个，不逐条列出整批。
- **进度每 tick 重建一整份快照**：比逐字段读多一次小对象分配，换来的是渲染线程永远读到自洽的一组数。
- **燧石在手持时变成"魔杖"**：左键挖不动方块。右键无额外代价（燧石原版没有右键用途）。
  2026-10-15 前用木斧，因它左键能挖、右键能给原木去皮，干扰明显而换成燧石。
- **选区在客户端与服务端各存一份**：燧石点击既写本地那份（供线框**即时**绘制，等一个网络来回会有肉眼可见的延迟），
  又上报服务端那份（`/wrutils test new` 读的是它）。代价是两份理论上可能漂移——玩家若改敲 `/wrutils sel pos1`，
  客户端的线框不会跟着变。这是刻意换来的手感，不是漏写。
- **单人也不走直读捷径**：`isRunning()` / `progress()` / 文件 IO 在单人下同样走 payload。
  代价是单人多了序列化开销、状态晚一 tick；换来的是单人多人**同一条码路**——
  原先那条"只在单人成立"的捷径正是"单人可以、多人坏"的温床。
- **多人下这套功能只适合服主自控的服务器**：测试会改 gamerule、强制加载区块、**独占世界**（见方案风险 #6）。
  编辑器另有 OP 门槛（与 `/wrutils` 命令一致）——非 op 玩家打不开。
- **HUD 画在屏幕**左下角**（x=4，贴着底边）**——那里正是原版聊天区，**聊天有内容时会被压住**。
  这是按"左下角"字面实现的；若碍事，改成贴快捷栏上方或左上角都是一行的事，告诉我位置即可。
- **HUD 文字是硬编码中文**，没走语言文件（其余 UI 文案本来就是中英双份）。要出英文版的话得补 i18n。
