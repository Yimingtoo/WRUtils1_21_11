## 环境（最容易踩的部分）

- 容器里**只有 Java 21**，fabric-loom 1.18.2 要求 JVM 25 → **gradle 完全跑不起来**。
- **唯一的编译验证手段**：`./scripts/typecheck.sh`（javac + loom 缓存里 remap 好的 jar 拼 classpath）。**每个 Phase 都要跑**。它只做类型检查，不校验资源、refmap、运行时行为。
- **游戏内验证由用户手动做**：IDE 在容器内以仓库的 `run/` 为运行目录启动客户端。测试定义在 `run/saves/New World/wrutils1_21_11/tests/`。
- 改 **Java** 代码 → 用户必须**重启游戏**；改 **JSON** → 不用，引擎每次 `run` 都现读磁盘。
- 存档里的 JSON 是**手工从 `docs/examples/` 拷过去的**，不是软链。**改了示例文件必须主动提醒用户重拷**——本轮为此浪费过一次调试循环。
- 同类环境事实在 memory 里也有一份（`build-needs-jvm25-use-javac-harness`）。

**Phase 3 已知会暴露的风险**（主方案风险 #7）：测漏斗 / 箱子 / 比较器时，`onUse` 里可能有 `isCreative()` 分支，而 `FakePlayer` 的 GameMode 决定走哪条路。拉杆没暴露这个问题，漏斗很可能暴露。若出现"拉杆能点、漏斗点不动"，去查 GameMode 相关设置。

## 本轮踩过的坑（会重演）

1. **1.21.11 的改名潮。** `Entity.getWorld()` → `getEntityWorld()`；`ActionResult` 从枚举变接口（只能用 `isAccepted()`）；`GameRules` 变成注册表持有者；**一大批 gamerule 改名**（`doMobSpawning` → `spawn_mobs`、`doMobLoot` → `mob_drops`……注意 `random_tick_speed` 没变）。完整对照表见 [Phase2验证手册](Phase2验证手册.md) 的踩坑记录。
