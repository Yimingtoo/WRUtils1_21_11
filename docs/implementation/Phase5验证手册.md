## 3. 游戏内往返自检 - 未测试

```

```
→ `[WRT] roundtrip: 9 相等 / 0 不等`

（若你另外建了 `t1` 之类的测试，数字会相应变大。）

**不等**时会逐个列出：
```
[WRT] 往返不等: <文件>
  A=<原对象>
  B=<写回再读的对象>
```
照着 `A`/`B` 的差异定位——最常见的是 `area` 被写成 `{}`（应为 null 时整段省略）、
或 `nbtIgnore` 只写了差集（它会整体替换默认忽略表，必须写全量）。

单个测试也可以：`/wrutils test roundtrip <id>`。

## 5. 旧格式被拒绝 - 未测试

随便挑一个存档里的测试文件，**删掉 `"schemaVersion": 2,` 那一行**，再：
```
/wrutils test roundtrip <id>
```
→ 应报错而不是跑错：
```
[WRT] 往返失败: <文件>: 缺少 schemaVersion（旧的绝对坐标格式已废弃，坐标现为相对 origin 的偏移，迁移后请补上 "schemaVersion": 2）
```

**判定**：报错即可（这是设计意图——旧格式坐标是绝对值、新格式是偏移，**没法从内容上区分**，
任何"猜"都会静默跑错，所以宁可拒绝）。测完把那一行加回去。

版本号写别的值（如 `9`）同样应被拒绝：`不支持的 schemaVersion=9（当前为 2）`。

## 9. 从编辑器运行 - 未测试

点 **`lever_toggle`** 选中，再点底部 **「运行」**。

→ **界面立刻关闭**，聊天出现 `[WRT] running lever_toggle in minecraft:overworld`，随后测试正常跑完（`PASSED`）。

**为什么必须先关屏**：本界面 `shouldPause()` 返回 `true`，开着它时单人世界是**暂停**的，
`END_WORLD_TICK` 不再触发 → run 永远推进不了。所以「运行」按钮的内部顺序是
"先 `close()` 再发命令"。**若你看到 run 卡住不动，第一个要怀疑的就是这条。**

## 10. 运行中拒绝打开编辑器 - 未测试

1. 跑一个耗时较长的测试（如 `/wrutils test run long_running`，它有 600 tick）。
2. 在它还没结束时按 **K**。

→ 聊天提示 `[WRT] 测试运行中，无法打开编辑器  [停止测试]`，界面**不打开**。
末尾的「**\[停止测试\]**」是**可点击**的——点它会把 `/wrutils test stop` **填入聊天框**，按回车才执行（见 §13）。
之所以不直接执行：`/wrutils` 带权限要求，客户端解析会被判成 `PERMISSIONS_REQUIRED`，
从而弹出原版"此命令需要权限"的确认框——那个框是原版画的，我们改不了。

**原理**：单人集成服务器下客户端与服务端**同 JVM、共用同一个 `WrtTestEngine` 单例**，
所以客户端直接读 `WrtTestEngine.get().isRunning()` 即可，**不需要任何网络包**（Phase 5 未引入包层）。

> 若不拦，编辑器会把正在跑的 run 挂起（同 §9 的暂停问题）。

## 12. 刷新保留选中项 - 未测试

1. 点左列某个测试选中它（右列出现详情）。
2. 点底部 **「刷新」**。

→ 列表重扫，**选中项仍在**（右列详情不丢）。

**判定**：刷新后仍停在同一测试上。刷新只重扫目录、不重建控件——
若这里出错，先怀疑列表控件状态被清空。

**另一条**：点完「刷新」再把光标移开，按钮**不应一直保持高亮**。
原版按钮被点击时会拿到焦点并画出高亮框，而 `ParentElement.mouseClicked` 的顺序是
"先触发按钮回调、再 `setFocused(按钮)`"——所以清焦点只能在**下一帧**（`tick()`）做，
在回调里清会被随后覆盖。若这里又出现常亮，先看 `TestEditorScreen.tick()` 里那段。

## 13. 停止测试 - 未测试

两种触发方式：

- 直接命令：`/wrutils test stop`
- 点聊天提示末尾的「[停止测试]」——它只在"运行中按 K 被拒"时出现（见 §10）；
  点它是把命令**填入聊天框**，回车才执行（鼠标悬停会有提示）

→ 聊天出现 `[WRT] 已停止当前测试`；若当时并没有在跑，则报 `[WRT] 没有正在运行的测试`。

**中止后应当**：

1. 当前 run 立刻收尾，报告写为 **`ABORTED`**（在 `run/saves/New World/wrutils1_21_11/reports/`）；
2. **gamerule 与强制区块已还原**（核对手法见 [Phase3验证手册](Phase3验证手册.md)）——
   中止走的是与正常结束同一条 `finish` 路径，不是"直接丢弃"；
3. **录制保留**（按"失败保留"处理，聊天与报告里有 `replay:` 行）；
4. 若是 `runall` 批跑中途停止，**队列里剩下的测试不再继续跑**。

**验证步骤**：`/wrutils test run long_running`（600 tick，来得及操作）→ 跑的过程中执行 `/wrutils test stop`
→ 对照上面四条。

## 17. 坏方块串被拦下 - 未测试

1. 编辑任意一个条目，把 `方块串` 改成 `minecraft:not_a_block`。

→ 该输入框**立刻变红**；此时点 **「保存」** → 下方出现红色错误
（形如 `选中项的方块串非法: …`），且**文件不会被写入**。

2. 改回合法串 → 红色消失，可正常保存。

> 校验用的是 `/setblock` 同一个解析器（`BlockArgumentParser.block(..., allowNbt=true)`），
> 所以带 `{Items:[…]}` 的箱子 / 漏斗串也算合法。
> 保存前还会把**全部** setup / steps 的方块串再整体校验一遍，从列表里改坏的也拦得住。

## 18. 条目增删与重排 - 未测试

- **「上移」/「下移」**：只在**同一段内**换位（setup 与 steps 是两个独立列表，跨界换位没有意义）。
- **「删除」**：移除选中条目，选中位置自动回退一格。
- **「类型」**：仅在选中 step 时可用；place→use→assert 循环，切换时**保留 tick 与坐标**。
  assert 与其它类型互转时，原有的 `strict` / `nbt` / `redstone` 断言会**保留**（只换 `block`）。
- 列表过长时用**鼠标滚轮**滚动；新增或移动后选中项会自动滚入视野。

## 19. 按钮高亮与 Esc 返回 - 未测试

两处交互修正：

1. **编辑屏按 Esc 返回列表屏**（不是直接关回游戏），**且列表里仍选中原来那个测试**；
   列表屏按 Esc 仍是关闭整个界面。「返回列表」按钮同此。
2. **点过的按钮不再保持高亮**：两个界面里，点完按钮后不应留下焦点高亮框
   （原版点完按钮会拿到焦点并画出高亮，光标移开也不消失）。

**做法**：清焦点只能延后一帧——`ParentElement.mouseClicked` 的顺序是
"先触发按钮回调、再 `setFocused(按钮)`"，在回调里清会被随后覆盖。
所以两个屏都在 `mouseClicked` 命中控件时置一个标志，在 `tick()` 里清掉。
若又出现常亮，先看 `TestEditorScreen.tick()` / `TestEditScreen.tick()` 那两段。

> **注意**：编辑屏清焦点时要排除文本框——点输入框本来就该拿到焦点，
> 一并清掉的话会"一松手就失去焦点、根本没法输入"（初版踩过这个坑，见 §22）。

## 20. 坐标拾取 - 未测试

1. 在编辑屏选中一个条目（setup 或 step）。
2. 点 **「拾取坐标」** → 界面关闭，聊天提示"准星对准方块，按「拾取方块」键填入坐标（默认 P）…"。
3. 准星对准世界里的某个方块，按 **P**。

→ 回到编辑界面，该条目的 `坐标` 已变成刚指的方块；聊天里出现 `[WRT] 已填入坐标 (x, y, z)`。
列表里那一行也同步变了。

**要点**：

- 拾取用**专用键位**（默认 `P`），**不占左键**——不会误挖方块，也不跟其它 mod 抢左键。
- 只在"有待处理的拾取、且没开着任何界面"时生效，所以平时按 P 没有副作用。
- 想中途放弃：按 **K** 打开列表（打开列表即丢弃这次拾取）。
- 没选中条目时「拾取坐标」是灰的（禁用）。

## 21. 整体平移 - 未测试

两种触发方式，效果相同——把整台机器搬到别处，**相对偏移不变**：

- 点 **「拾取原点」** → 关屏 → 准星对准**新位置的原点方块** → 按 **P**；
- 或直接在 `原点` 输入框里改坐标。

→ 聊天提示 `[WRT] 已整体平移 (dx, dy, dz)`；列表里**所有**条目的坐标、以及 `原点` 本身，
同时平移了同一个 delta。

**判定**：

- 平移后保存，`/wrutils test roundtrip <id>` 仍相等；
- **JSON 里除 `origin` 外应当没有任何变化**——因为存的本来就是相对 `origin` 的偏移。
  这也是"整体平移"能退化成改一个字段的原因。

> 注意 `原点` 输入框是**逐字符实时生效**的：打 `300` 的过程中会先按 `3`、再按 `30` 平移。
> 因为平移可叠加（先移 a 再移 b = 移 a+b），**最终结果与一次到位相同**；
> 但若在打到一半时离开该输入框，就会停在中途的位置。

## 22. 输入框的焦点与禁用 - 未测试

1. 点 `id` / `超时` / `原点` / `描述` 任一输入框 → 应能正常聚焦并输入。
   （§19 那版把焦点一律清掉，导致这几个框**根本改不了**——这是回归，已修。）
2. 不选中任何条目时，表单里的 `tick` / `坐标` / `方块串` 应**点不动**，
   不再出现"闪一下高亮、随后又变灰"。

**做法**：

- 清焦点只对**按钮**做——编辑屏在 `mouseClicked` 里判断"新焦点是不是 `TextFieldWidget`"，是则**不清**。
- 禁用输入框要连 `active` 一起关：`ClickableWidget.mouseClicked` 只查 `isInteractable()`，
  光调 `setEditable(false)` 点击照样会被处理。见 `TestEditScreen.setFieldEnabled(...)`。

## 23. 可写区屏 - 未测试

在编辑屏点 **「可写区」**。

→ 打开 `WRT 可写区` 屏：

- **列表**：每行一个矩形，形如 `area[0]  (0, 0, 0) .. (1, 0, 2)   体积 N`；点一行即选中
- **表单**：`min` 与 `max` 两格（`x y z` 形式），实时改选中区域；`Region.of` 会归一化，min/max 写反也没关系
- **按钮**：`＋区域` / `删除` / `拾取角1` / `拾取角2` / `返回`

**操作**：

1. `＋区域` → 多出 `area[N]`，默认是 `origin` 那一格（选中它）。
2. `拾取角1` → 关屏 → 准星对准方块按 **P** → 回来时该角已设好；`拾取角2` 同理。
   **两个角先拾哪个都行**（归一化会处理）。
3. 也可以直接在手改 `min` / `max` 输入框。
4. `删除` 移除选中区域；删到 0 个时列表会红字提示"任何 place/use 都会被拒绝"。

**判定**：`返回` 回到编辑屏；`保存` 后打开 JSON，`area.input` 是**数组**，元素个数与屏上一致。

## 24. 多可写区生效 - 未测试

要验的是"可写区可以由**多片互不相邻**的矩形组成"，这正是 5.5 的动机。

1. 在「可写区」屏建**两个**区域，刻意让它们**中间隔开一段**：
   比如 `area[0]` 覆盖拉杆附近，`area[1]` 覆盖 5 格外的一个点。
2. 加一个 `place` 或 `use` 步骤，坐标落在 **area[1]** 里 → 保存 → `/wrutils test run <id>` 应当**正常跑**。
3. 把那个步骤的坐标改到**两片之间**（哪片都不在）→ 保存 → 运行。

→ 第 3 步应当在启动阶段被拒，错误信息形如：

```
place 步骤 位置 (x,y,z) 在可写区 [a]..[b] | [c]..[d] 之外：只有输入区内的方块可以被修改
```

**注意**：错误信息里会用 ` | ` 分隔列出**全部**可写区——这是判断"引擎确实按多个区域判定"的直接证据。

**顺带回归**：`/wrutils test runall` 仍应是 **7/9**（`lever_toggle_fail` FAILED、`input_boundary_violation` ABORTED）。
若结果变了，说明多选区改造动了既有语义，要回查 `TestRun.chunkRegion` 与 `WorldPrep.clearInput`。
