## 最近做完的事：多人服务器支持

设计细节见[主方案](../redstone-unit-testing-plan.md) Phase 6 一节，这里只记**与当初计划不同的三处判断**
（下个会话若照着旧计划走会重复讨论）：

1. **payload 是 4 个，不是计划里的"约 5 个"**——"删"砍掉。编辑器根本没有删除测试文件的入口
   （界面上两个"删除"删的是内存里的条目与可写区，全仓也没有删测试文件的代码）。
   > **2026-10-17 补记（P7b）**：删除测试文件已实现——`TestEditorOp.DELETE`、
   > `/wrutils test delete <id>`、编辑器「删除」按钮（带二次确认）。上面只代表 Phase 6 当时的取舍。
2. **没抄 `replay/` 的 `Backends.select + Noop` 降级骨架**——那套的前提是存在多个互斥后端
   （装没装 server-replay），而 Fabric 网络只有一种机制且永远可用。照抄只会多一个永远选不中的类。
3. **单人也不走直读捷径**——`isRunning()` / `progress()` / 文件 IO 单人同样走 payload。
   这是用户拍板的，也是本轮**最大的取舍**：代价是序列化与晚一 tick，换来单人与多人同一条码路。

**验收后修了两处**（都是 §24 / §31 的备注引出来的）：

- **客户端镜像的状态泄漏**：服务端是**边沿触发**广播（空闲→空闲不发），"最后收到 `running=true`、
  却在测试结束前断了线"的客户端会永久卡在"正在跑测试"——燧石选不了点、编辑器打不开，
  而选区 HUD（它不查 `isRunning`）照旧显示"开启"。现在在 `ClientPlayConnectionEvents` 的
  JOIN / DISCONNECT 上复位 `ClientTestState`，并按 UUID 清掉本客户端的选区（**不清全局**：
  单人开 LAN 时客户端与服务端共用同一个 `SelectionManager`）。
- **编辑器"新建"从不读燧石选区**（Phase 5 就存在的空白，不是本轮引入的）——原先一律用
  `client.player.getBlockPos()`，于是"圈好了范围、点新建却建在脚底下"。改为有选区就用选区
  （`origin` 取 min 角，与 `/wrutils test new` 同义），没选区或只选一端才退回玩家脚下。

### 两条容易再踩的坑

- **凡是把本地权威状态换成"镜像"，都要想清楚什么时候复位。** 直读单例没有这个问题，镜像是新增的
  一条可能不同步的路径——这一轮的缺陷就是这么来的。
- **集成服务端暂停时仍处理网络包**（单人下全靠它）：`MinecraftServer.processPacketsAndTick` 里
  `packetApplyBatcher.apply()` 是**无条件**执行的，暂停只影响其后 `tick()` 的 keep-ticking 判断。
  反编译核对过；"开背包世界暂停但物品照常移动"是同一个道理。若该假设在某版本失效，
  表现为编辑器在单人下**永远停在"加载中…"**。

## 环境（最容易踩）

### 两套并存的运行方式（互斥，都盯着 `run-server/`）

| | dev 运行（推荐开发用） | 独立服务器 |
|---|---|---|
| 客户端 | `:runClient`，目录 `run/` | — |
| 服务器 | `:runServer`，目录 `run-server/` | `java -jar run-server/launcher.jar nogui` |
| 起法 | IDEA 的 Gradle 配置 `Minecraft Client` / `Minecraft Server` | `scripts/run-server.bat`（Win）/ `.sh`（容器） |
| 改代码 | **重启即可**，不用构建 | 要 `Build Jar` + 重新拷 jar |
| 适合 | **开发多人功能** | 最后一轮验收（验生产 jar） |

- **两套互斥的根源是 `run-server/mods/`**：dev 运行把 mod 放在 **classpath** 上，`mods/` 里再放一份会
  **同 mod id 加载两次而崩**。所以走 dev 路线时，`run-server/mods/` 里**只能有** ServerReplay 与
  fabric-language-kotlin（`run/mods/` 同理，另多一个客户端用的 replaymod）。
- `build.gradle` 里为此加了两处：`loom.runs.server.runDir "run-server"`（否则 `runServer` 与 `runClient`
  抢同一个 `run/`，**根本无法同时跑**）和 `loom.runs.client.programArgs "--username", "player001"`。
- **改完 `build.gradle` 必须在 IDEA 里重载 Gradle 项目**，否则改动不生效。

## 顺手修掉 / 需要知道的三件事

- **`.bat` 的换行被钉死了**：`.gitattributes` 原本只有 `* text=auto`，那样 `.bat` 检出时的换行
  取决于检出机器的 `core.eol`——LF-only 的批处理在 `cmd.exe` 里解析可能出错。已加
  `*.bat text eol=crlf`（仓库里存 LF，检出永远是 CRLF）。**以后新增 `.bat` 不用再操心这件事。**
- **`run-server/` 曾整个躺在暂存区里**（258 个条目：`launcher.jar`、两个 ~17MB 的 mod jar、整个 `world/`、
  以及含密钥的 `server.properties`）。根因是 `.gitignore` 里写的是 `run/`，**匹配不到 `run-server/`**。
  已处理：`.gitignore` 加上 `run-server/`，并 `git reset -- run-server` 移出暂存区（**磁盘上 353 个文件一个没动**）。
- **`.idea/` 是被根 `.gitignore` 忽略的**（第 2 行）。所以 `.idea/runConfigurations/` 下我写的
  `Build_Jar.xml` 与 `Minecraft_Server_Standalone.xml` **只存在本地、不随仓库走**。
  （会话中我曾说错一次，说它们可提交——以本节为准。）
