## Description

### 1. Phase 3 — 断言深度 + 报告

- `Expectation` 由单字段扩为 `(block, strict, nbt, redstone)`，三个条件各自独立检查、可同时存在（一条 assert 可产出多条 Failure）。
- 新增 `NbtSubsetMatcher`（子集/全等，数值按 `doubleValue` 比较，列表要求长度相等——**语义对齐原版 `/execute if data`**）、`RedstoneMatcher`（`received`/`strong`/`emitted`）。
- `Failure` 加 `kind`，并以 `Failure.describe(...)` 作为聊天/日志/报告 TXT 的**唯一文本来源**。
- 新增 `ReportWriter` 落盘 `<存档>/wrutils1_21_11/reports/<时间戳>-<id>.json` + `.txt`。
- `runall`：串行队列 + 总表；不放松"同一时刻只跑一个 run"。
- **顺带补全**：`place` 步骤此前丢弃方块串里的 NBT → 现在经 `NbtReadView.create(...)` 写入方块实体（1.21.11 的 `BlockEntity.read` 收 `ReadView` 而非 `NbtCompound`），否则箱子/漏斗的 NBT 断言无从验证。

**实测暴露并修复**：
1. `BlockArgumentParser.block(...).nbt()` 在无 `{...}` 时返回 **null**（非空 compound）→ 所有无 NBT 的 `place` 在 tick 0 NPE、整批 ABORTED。
2. `ignoreKeys` 原实现递归生效，会误伤 `Items` 里物品自身的 `id` → 收窄为**只作用于顶层**，并把 `components` 加入默认忽略（否则 `exact` 对任何方块实体都必失败）。
3. `runall` 在某个测试**启动失败**时卡死（推进挂在 `onEndWorldTick`，`currentRun` 一空就断链）→ `startNext()` 改循环推进。
4. 启动失败**不落盘**（磁盘上凭空少一条）→ 补写 `ABORTED`/`kind=startup` 报告。
5. 失败信息 `exp` 显示**补全默认属性后**的状态（如 `lever` 的 `face=wall`）→ 改为显示作者写的原串；非步骤类失败不再显示 `step#-1`、也不再打空的 `exp`/`act`。

### 2. 非破坏性测试改造

动机：实际用法是**在已建好的红石机器上测试**，原先"清空整片区域"会把机器毁掉。

- `area.input`（矩形 `{min,max}`）是**唯一允许被修改**的范围；`place`/`use` 越界 → 在 `TestRun` 构造时拒绝（不碰世界）。
- `area.cleanup`：可选清理策略——**仅实现 `clear_input`**（跑前清空可写区、跑后不还原）；`none`/`snapshot` 已进 schema 但未实现，选用即报错。
- `forceChunks`/`clearEntities` **默认 false**；强制区块范围 = 可写区 ∪ 全部步骤坐标。
- 旧字段 `radius`/`clearArea` 一旦出现即报错（不给静默跑错的机会）。

### 3. 命名：`isolate` → `area`

JSON 键、记录类（`IsolationSpec` → `AreaSpec`）、`TestDefinition` 字段三层同步改名；旧键 `isolate` 出现即提示改名。

### 4. Phase 4 — 录制后端

- 接口只走**字符串命令**（`RecordBackend`/`RecordingSession`/`RecordingTarget`），无 ServerReplay 也能编译运行；探测不到就降级 `NoopRecordingBackend`（只 warn 一次）。
- 每测试全程录制；**通过传 `save=false` 丢弃 + 延迟 glob 删除兜底**；失败保留并把路径写进报告 `recording` 字段。
- `recording status|test` 两条命令；`SERVER_STOPPING` 保留现场；`fabric.mod.json` 加 `recommends: server-replay`。
- 自建配置 `<runDir>/config/wrutils1_21_11.json`。

**实测暴露并修复**：
6. 录制半径原按测试区大小算，小测试只录 3×3 区块 → 回放"一步到虚空"；改为 `max(测试跨度, 8) + 外扩1`。
7. 通过后留下**空目录** → 兜底清理顺带删空目录。
8. 按需求新增**前后预留** `recordingPaddingSeconds`（默认 1.0，测试前后各留一段；只在真录制时生效、不计入 `relativeTick`），并因此把 `timeoutTicks` 的判定收窄为"步骤未跑完时"。

**已确认的环境事实**：`chunks` 模式的回放 `selfId = -1`，是**自由相机**，初始位置跟随录到的玩家——跑测试前 `/tp` 到测试区即可（属 ReplayMod/ServerReplay 行为，命令层无法设置）；`FakePlayer` 不在录制里（UUID 不在 `players` 列表），无法靠 spectate 定位相机。
